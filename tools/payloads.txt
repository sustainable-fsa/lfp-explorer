# The data payloads this app fetches at runtime — the staging manifest.
#
# This repo ships no data. Every payload is fetched by RELATIVE sibling path
# (../<repo>/<file>) which production resolves to that archive repo's
# same-origin GitHub Pages copy, and which the harnesses resolve against the
# workspace root they serve. One line per published artifact, as
# <repo-dir>/<file> — the path is the same on sustainable-fsa.com and in the
# workspace, which is the whole point of the convention.
#
# CI (.github/workflows/audit.yaml) loops this file and curls each artifact
# into its sibling slot; `curl -f` fails the step on a missing one, which is
# the correct signal — those origins are part of the app's contract. Locally,
# mirror it from the repo root when a sibling checkout is absent:
#
#   while IFS= read -r p; do
#     case "$p" in ''|\#*) continue ;; esac
#     mkdir -p "../$(dirname "$p")"
#     [ -f "../$p" ] || curl -fsSL "https://sustainable-fsa.com/$p" -o "../$p"
#   done < tools/payloads.txt
#
# THE RULE: a line lands in the SAME commit that makes the app fetch it, so
# staging can never lag the app. Blank lines and #-comments are ignored.
#
# The FIPS↔FSA crosswalk is deliberately absent: it is a committed repo asset
# (assets/fsa-fips-crosswalk.json), served by the checkout itself.

# 1 · Grazing periods — the boot payload, and the only fetch on the boot path.
fsa-normal-grazing-period/fsa-normal-grazing-period.json

# 1 · Grazing periods — nClimGrid climatology, fetched lazily on first toggle.
nclimgrid-normal-grazing-period/nclimgrid-normal-grazing-period.json

# 2 · Drought monitor — the weekly USDM, one worst-class series per county for
# every week since 2000-01-04. Three answers to the same question, differing
# only in what a "county" is; all three are FIPS-keyed and reach the FSA
# composite through the crosswalk. All fetched lazily, on the switch or the
# dataset toggle that asks for one.
#
# FSA's own FOIA'd LFP boundary statistics — this view's default.
usdm-counties-fsa-lfp/usdm-counties-fsa-lfp.json
# NDMC's published county statistics, as published (Connecticut is keyed as its
# nine planning regions, which no FSA county covers — the app counts them out
# loud rather than dropping them).
usdm-counties-reported/usdm-counties-reported.json
# Vintage-matched TIGER counties: the one non-rectangular set, where a county
# absent from a week is absent in the data too.
usdm-counties/usdm-counties.json

# 3 · LFP eligibility — one record per qualifying drought event, at the grain
# the program itself uses: Census county × FSA county × program year × pasture
# type × tier. All three are FSA-keyed (each carries a `counties` dictionary of
# FSA ids and a parallel `fips` column into a separate Census dictionary), so
# none of them touches the crosswalk. All fetched lazily.
#
# FSA's own determinations, obtained by FOIA — program years 2008–2025. This
# view's default, and the only payload in the app whose record ends before the
# app's default year.
fsa-lfp-eligibility/fsa-lfp-eligibility-events.json
# The same determinations as FSA publishes them week by week on its maps page —
# 2008 through the current program year, and the only one of the three that
# carries per-tier dates for 2008–2011.
fsa-lfp-eligibility-web/fsa-lfp-eligibility-web-events.json
# Eligibility RECOMPUTED from the Drought Monitor under four county-aggregation
# conventions — not a record of FSA's determinations, and the largest payload in
# the app (~11 MB: it holds all four aggregations side by side). It carries the
# drought factor the ladder awards and no payment cap, so what it shows is not
# the payable amount.
fsa-lfp-eligibility-derived/fsa-lfp-eligibility-derived.json
